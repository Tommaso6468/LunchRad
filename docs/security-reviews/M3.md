# Security review — M3 The arcade reel

Date: 13 November 2026. Scope: `start_spin`, reel construction and winner
selection, room phases and locking, the reel, lever and result screens.

## What changed

- `start_spin` (host only, no parameters). The room builds the reel (each
  restaurant once, plus one row per boost), picks the winning row with
  `crypto.getRandomValues` and rejection sampling, stores it, and broadcasts
  reel, winner, duration and elapsed time.
- Phases `lobby` → `spinning` → `result`; the room alarm moves to `result`
  when the 5-second animation time is over.
- Adding, removing, boosting and unboosting are refused from the moment the
  spin starts.
- App: full-screen reel that opens on every phone when the spin starts, lever
  for the host, drum with perspective, reduced-motion variant (1 s), result
  card with Maps link, result above the locked list.

## Findings

| #   | Finding                                                                                               | Severity | Status                                                                                   |
| --- | ----------------------------------------------------------------------------------------------------- | -------- | ---------------------------------------------------------------------------------------- |
| F1  | First reel layout could put a boosted restaurant's rows next to each other (by chance or at the wrap) | Info     | Fixed: "most overdue" placement plus a repair pass; tested on 200 random reels per run   |
| F2  | Every participant learns the winner when the spin starts, 5 s before the animation shows it           | Info     | Accepted: the result is fixed at that moment anyway; hiding it would only be theatre     |
| F3  | A phone whose clock or connection is slow may stop a fraction later than the others                   | Info     | Accepted: the server's elapsed time is used, so the difference is the network delay only |

## Residual risk

Low. The result cannot be influenced by any client: the message that starts
the spin carries no data, the host check is on the server, the odds are
locked when the lever is pulled, and the random source is the platform CSPRNG.
