# Security review — M2 Restaurants and boosts

Date: 13 November 2026. Scope: restaurant input (name, category, Google Maps
link), adding and removing restaurants, boosts, the restaurant list and add
dialog, merged toasts.

## What changed

- New WebSocket messages: `add_restaurant`, `remove_restaurant`, `boost`,
  `unboost`. New events: `restaurant_added`, `restaurant_removed`, `boosted`.
- Room state now carries the restaurants and each participant's boost.
- Shared rules for names and categories (letters, digits and a short list of
  punctuation) and for Maps links (allow-list).
- Seed preset file, empty until the real list is supplied; a test validates it.
- App: restaurant list with share of the wheel, boost toggle, Maps link,
  remove; add dialog on native `<dialog>`; toasts merged within 2 seconds and
  never for your own actions. Team key field only turns red for a wrong key.

## Checklist

- [x] Threat model updated to v3 (T5, T6, D2 added; E1 implemented)
- [x] Every new message: authenticated socket, permission check (host or owner for removal),
      Zod schema, character rules, 2 KB size limit, per-socket rate limit
- [x] Abuse tests: markup in names and categories, `javascript:`, `data:`, look-alike hosts,
      credentials in URLs, other ports, non-owner removal, unknown ids, 31st restaurant,
      duplicate names, boosting a removed restaurant, kicked participant's boost
- [x] CI clean locally: 73 Worker, 26 shared and 9 app tests; lint; typecheck; build; `npm audit` 0
- [x] End-to-end in Chromium, three phones and dark mode: add with category and Maps link,
      bad link refused in the dialog, duplicate refused by the server with a toast, boost,
      move boost, odds update, host removes a boosted restaurant and the booster is told.
      Changes reached the other phone in 32 to 58 ms. No console errors.
- [ ] On staging (owner): M1 finding F8 still open (Turnstile with Trusted Types)
- [ ] OWASP ZAP baseline against staging (owner)
- [x] Findings below fixed or accepted

## Findings

| #   | Finding                                                                                                | Severity | Status                                                                           |
| --- | ------------------------------------------------------------------------------------------------------ | -------- | -------------------------------------------------------------------------------- |
| F1  | A first draft of the Maps check was a tangle of conditions that was hard to verify                     | Low      | Fixed: rewritten as a host → path allow-list table, with 14 rejection tests      |
| F2  | Every change broadcasts the full state (up to ~18 KB with 30 long links) to every socket               | Low      | Accepted: outgoing messages are not billed; 20 people × 18 KB per change is fine |
| F3  | Moving a boost twice within 2 s shows "2 nieuwe boosts", although it was one person moving their boost | Info     | Accepted: cosmetic                                                               |
| F4  | Anyone in the room can add up to the 30-restaurant cap on their own                                    | Info     | Accepted: teammates; the host can remove anything                                |
| F5  | Link hosts such as `maps.app.goo.gl` are redirectors: the final page is chosen by Google, not by us    | Info     | Accepted: only Google's own short links are allowed, and they open in a new tab  |

## Residual risk

Low. User input now reaches other people's screens, but only as text through
Angular's escaping, under a CSP without inline script and with Trusted Types,
and links only point to Google Maps. M1's open item F8 still needs the owner's
check on staging.
