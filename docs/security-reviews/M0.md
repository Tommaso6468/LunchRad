# Security review — M0 Foundation

Date: 20 October 2026. Scope: repository setup, app shell, Worker, CI/CD.

## What changed

- Angular v22 app shell (Dutch), served through a Cloudflare Worker.
- Worker serves the HTML shell with a fresh 128-bit CSP nonce per request;
  static assets are served by Cloudflare with headers from `app/public/_headers`.
- CI: lint, format, banned-API check, typecheck, tests, build, `npm audit`,
  dependency review, OSV-Scanner, gitleaks, CodeQL (TypeScript and Actions, fails on findings).
- Deploys: staging after green CI on `main`; production only from a published
  `vX.Y.Z` release on `main`, after full re-verification and manual approval.

## Testing done

- Worker tests run inside workerd: nonce is fresh per request, identical in the
  CSP header, `app-root`, `<script>` and `<link>`; CSP has no `unsafe-*`;
  shell is `no-store`; baseline headers on every route; `_headers` file matches
  the Worker baseline.
- Loaded the built app in headless Chromium through `wrangler dev` with the
  production CSP: renders, component styles apply via the nonce, Trusted
  Types active, self-hosted font loads, **zero console errors or CSP violations**.
- Lint rules verified to fail on `Math.random`, `innerHTML` and the banned-API
  script on raw-HTML writes.

## Findings

| #   | Finding                                                                                   | Severity            | Status                                                                         |
| --- | ----------------------------------------------------------------------------------------- | ------------------- | ------------------------------------------------------------------------------ |
| F1  | `base-uri 'none'` blocked Angular's `<base href="/">`, so the app did not start           | High (availability) | Fixed: `base-uri 'self'` on the shell; APIs keep `'none'`                      |
| F2  | Angular's critical-CSS inlining emits `onload` handlers that a strict CSP blocks          | Medium              | Fixed: `inlineCritical: false` in the production build                         |
| F3  | Without `run_worker_first`, `/` and `/index.html` would bypass the Worker and its CSP     | High                | Fixed: both routes run the Worker first; covered by the smoke test             |
| F4  | Missing asset paths could return the HTML shell (MIME confusion, cache poisoning surface) | Low                 | Fixed: paths with a file extension return 404                                  |
| F5  | HSTS without `preload`                                                                    | Info                | Accepted: `.dev` is HSTS-preloaded as a whole TLD, so `workers.dev` is covered |
| F6  | Account takeover of GitHub/Cloudflare/admin email bypasses all controls                   | High                | Mitigation is owner setup (passkeys, scoped token, rulesets): docs/setup.md    |

## Residual risk

Low. The app has no user input or state yet. The main open items are the two
staging checks above and the account hardening steps, which only the owner can do.
