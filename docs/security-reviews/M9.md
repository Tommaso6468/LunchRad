# Security review — M9 Big-screen mode

Date: 14 November 2026. Scope: display tokens in the room, the display
socket, `/scherm/CODE`, the host's link dialog, Wake Lock and fullscreen.

## What changed

- Host-only `create_display`: the room makes a 256-bit token, stores only
  its SHA-256, closes any screen on an earlier token and sends the token to
  the asking host's socket alone.
- `display_hello {token}`: a socket with the right token becomes a display.
  A display gets `display_welcome` and every state and event, and may send
  nothing: every message is answered with `not_allowed` (pings are answered
  by the runtime). It is not a participant, never counted as connected,
  never eligible to vote, has no hello timeout, and a room with only a
  screen left still closes as empty.
- The link is `/scherm/CODE#token`: the token is in the fragment, so it is
  not sent in requests or Referers; the page moves it to sessionStorage and
  removes it from the address bar. The WebSocket still needs a team session.
- Big-screen page (lazy-loaded): lobby with big code, QR and odds; the reel
  during the spin; winner and live vote; confetti; Wake Lock; fullscreen.

## Findings

| #   | Finding                                                                                  | Severity | Status                                                                                   |
| --- | ---------------------------------------------------------------------------------------- | -------- | ---------------------------------------------------------------------------------------- |
| F1  | Anyone with the screen link and the team key can watch the room until a new link is made | Low      | Accepted: watching only; the host can revoke by making a new link; rooms last 30 minutes |
| F2  | The big screen had no page heading in the reel and vote phases                           | Info     | Fixed                                                                                    |
| F3  | "Sluit over 6 minuten" right after the result (clock lag in the countdown)               | Info     | Fixed on the big screen and on phones                                                    |

## Residual risk

Low. A display can only receive what every participant already sees.
