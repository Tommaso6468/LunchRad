# Security review — M6 PWA and polish

Date: 14 November 2026. Scope: web app manifest and icons, the service
worker and its delivery, offline and update notices, sound, vibration,
confetti, the sound switch, accessibility and responsive fixes.

## What changed

- Manifest (`manifest.webmanifest`), icons (SVG, PNG, maskable, Apple touch
  icon), theme colours fixed to the current palette.
- Hand-written service worker (`app/sw/sw.js`, built by
  `scripts/build-sw.mjs`): precaches the content-hashed build output and the
  icons; pages network-first with the cached shell only as offline fallback;
  `/api`, `/admin` and `/sw.js` never cached; other origins untouched. A new
  version waits until the person taps "Vernieuwen".
- `/sw.js` is served by the Worker with `Cache-Control: no-cache` and a CSP of
  its own (`default-src 'none'; connect-src 'self'`). The page registers it
  through the Trusted Types policy `lunchrad#sw`, which accepts `/sw.js` only;
  the shell CSP lists that policy.
- Web Audio sounds (lever, ticks, landing, final fanfare), `navigator.vibrate`
  on Android, a confetti canvas on the final result (skipped with reduced
  motion; randomness from `crypto.getRandomValues`). One switch, remembered on
  the device.
- Accessibility: room page has a heading; the room code no longer puts
  `aria-label` on a plain span; dark mode buttons and the winner's name now
  meet 4.5:1 contrast.

## Findings

| #   | Finding                                                                                                 | Severity | Status                                                                                                                   |
| --- | ------------------------------------------------------------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------ |
| F1  | A service worker with the page's static-asset CSP (`default-src 'none'`) could not fetch anything       | Info     | Fixed: `/sw.js` goes through the Worker with `connect-src 'self'`; tested                                                |
| F2  | `register()` is a Trusted Types sink; without a policy registration would fail (or need a loose policy) | Low      | Fixed: dedicated policy that accepts exactly `/sw.js`                                                                    |
| F3  | The offline shell keeps the nonce it was fetched with                                                   | Info     | Accepted: used only when offline, with its own matching CSP header; online loads always get a fresh nonce                |
| F4  | A broken release could stay on phones through the cache                                                 | Low      | Mitigated: `sw.js` is never HTTP-cached, the browser checks it on every visit and when the app returns to the foreground |
| F5  | Contrast failures in dark mode (white on tomato 3.9:1, red name on dark green)                          | Medium   | Fixed: tomato kept at the light value (4.96:1), separate lighter red for text (6.2:1)                                    |
| F7  | CodeQL `js/missing-origin-check`: the worker's message handler did not check the sender's origin        | Low      | Fixed: messages from any other origin are ignored (browsers already only let same-origin pages post to it)               |
| F6  | Room code read via `aria-label` on a span (not reliably announced)                                      | Low      | Fixed: visually hidden text with spaced characters                                                                       |

## Residual risk

Low. The service worker can only serve this origin's own build files and
never stands between the app and the API, the WebSocket or the admin panel.
