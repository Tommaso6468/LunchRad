# Security review — M8 Hardening and launch

Date: 14 November 2026. Scope: the whole application as it will launch
(M0–M7), plus the operational side: rate limits, backups, runbook.

## What was done

1. **OWASP ZAP full scan** (ZAP 2.17.0, checksum verified) against the real
   Worker bundle in Miniflare, authenticated as a team member and as an admin
   (team session, Access token, admin header and Origin added to every
   request, so the active scan reached the admin API's changing endpoints).
   Seeded with every page and API route, then spider and active scan.
   A repeatable unauthenticated scan of staging through Cloudflare's edge is
   added as a manual workflow (`Security scan (staging)`).
2. **Black-box abuse tests**: 52 attacks against the same bundle with the
   production rate limits (`scripts/security/abuse.py`, local only).
3. **Rate limits reviewed for real use**: one office behind one IP.
4. **D1 restore**: drill automated on staging (`D1 restore drill (staging)`).
5. **Runbook**: `docs/runbook.md`.
6. **Launch checklist**: `docs/setup.md` part 7.

## ZAP results

| Alert                                                                            | Risk (confidence) | Verdict                                                                                                                                                                                                                                                                                                                               |
| -------------------------------------------------------------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Path Traversal on `name` of `POST /api/rooms`, `/join`, `/admin/api/restaurants` | High (Low)        | False positive. ZAP sent the URL's last segment ("rooms", "join") as the name and got a similar answer: a room or restaurant with that name. Names are display text only, never used in a path, file or query; both are validated against a strict character set. Marked out of scope for this rule on those URLs in `.zap/rules.tsv` |
| Hidden File Found (`/._darcs`)                                                   | Medium (Low)      | Was a false positive (the app shell answered 200 for any route). Fixed anyway: every path segment starting with a dot now answers 404 (F3)                                                                                                                                                                                            |
| Suspicious Comments (`admin`, `db`)                                              | Info              | False positive: words inside minified code, no comments ship                                                                                                                                                                                                                                                                          |
| Modern Web Application, Session Management Response, User Agent Fuzzer           | Info              | Informational, expected for this app                                                                                                                                                                                                                                                                                                  |

No other alerts: no injection, XSS, CSRF, header, cookie or CSP findings.

## Abuse tests (52/52 passed)

Methods other than GET/POST; path tricks to reach the admin API without
Access (`/api/../admin`, `//admin`, `/ADMIN`, `%2F`, `%2e%2e`); probing for
`.env`, `.dev.vars`, `wrangler.jsonc`, `.git`, source maps; a 5 MB body;
`__proto__` and form-encoded bodies; team-key guessing from one IP and from
many; forged and unsigned team sessions; room probing without a session;
markup, bidi, zero-width, NUL, quote and lookalike names; case-variant
duplicate names; WebSockets from a foreign Origin, without or with a forged
team token, with a wrong or another room's participant token, silent past
the hello timeout, oversized, flooding, binary, with a chosen winner; double
voting from two sockets of one participant; a kicked participant coming
back; more than 60 sockets in a room; admin calls with an `alg: none` token.

## Rate limits after review

| Limit (per IP, per minute, per location)  | Before | After | Why                                                               |
| ----------------------------------------- | ------ | ----- | ----------------------------------------------------------------- |
| Team key attempts                         | 10     | 20    | A whole office (one IP) entering the key at once                  |
| Team key attempts, all IPs together       | none   | 30    | New: guessing from many IPs in parallel gets nowhere              |
| Room creation                             | 5      | 5     | Plenty; Turnstile as well                                         |
| Joining and read endpoints (stats, lists) | 60     | 60    | Read endpoints were unlimited; stats reads the whole history (F4) |
| WebSocket connects                        | 120    | 300   | 20 phones reconnecting after sleep or a Wi-Fi switch              |

Hits are logged as `Rate limited` with the route only (never the IP), so the
limits can be tuned with real data from Workers Observability.

## Findings

| #   | Finding                                                                                                   | Severity | Status                                                                                                                               |
| --- | --------------------------------------------------------------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| F1  | Lookalike names: "Тоm" with Cyrillic letters looked exactly like "Tom" and was accepted                   | Low      | Fixed: names mixing Latin with Cyrillic or Greek are refused; single-script names still work                                         |
| F2  | Team-key guessing was limited per IP only; many IPs could guess in parallel                               | Medium   | Fixed: extra limit across all IPs (30/min per location)                                                                              |
| F3  | Any path, including `/.git/config`, answered 200 with the app shell (scanner noise, no data)              | Info     | Fixed: dot paths answer 404                                                                                                          |
| F4  | `GET /api/stats` and `/api/presets` had no rate limit; stats reads all history rows (D1 daily read quota) | Medium   | Fixed: 60/min per IP                                                                                                                 |
| F5  | Per-IP limit of 10 team-key attempts would block an office onboarding together                            | Low      | Fixed: 20/min per IP                                                                                                                 |
| F6  | The app could be indexed by search engines                                                                | Info     | Fixed: `X-Robots-Tag: noindex` on every response and `robots.txt` disallowing everything                                             |
| F7  | A foreign `Host` header ends up in the shell's CSP `connect-src`                                          | Info     | Accepted: Cloudflare routes by hostname, so such a request never reaches this Worker; it would only affect the sender's own response |
| F8  | Rotating `SESSION_SECRET` silently invalidates a team key set in the admin panel                          | Low      | Documented in the runbook: set a new team key right after                                                                            |
